## 4. Persistence specification

### 4.1 Normative conventions

All SQL below is **proposed PostgreSQL 16 DDL**, not existing Flyway migrations. Tables are created in dependency order within each schema. Every tenant-owned row has non-null `tenant_id`; the tenant root itself uses `id` as the tenant identifier. No FK crosses service schemas. Foreign employee/user IDs are local projection references or opaque audited actor IDs. All ordinary entity primary keys are `(tenant_id,id)`; natural/composite projections explicitly state their key. Mutable tables add `created_at timestamptz NOT NULL DEFAULT now()`, `updated_at timestamptz NOT NULL DEFAULT now()`, `version bigint NOT NULL DEFAULT 1 CHECK(version>0)`. Immutable tables add only created_at; normal runtime grants prohibit UPDATE/DELETE on evidence, ledger, decision-action, and audit tables. Application writes maintain updated_at/version atomically; no trigger behavior is assumed. An immutable request for correction is distinct from its mutable summary/projection: the action ledger preserves decisions. All tenant FK references include tenant_id; UUID uniqueness by itself is not an authorization boundary. `uuid` IDs are generated by the application; no database UUIDv7 extension is assumed. Notations use actual SQL nullability: omitted NOT NULL means nullable. PK columns are inherently NOT NULL. JSONB columns are bounded and validated by typed application schemas; jsonb type alone is not payload validation. Foreign IDs to other services have no FK, but are checked against local ref tables where available.

Retention profiles (periods require O05 approval):

| Profile | Tables | Rules |
|---|---|---|
| MASTER | Org/types/catalogue/templates | Soft-delete when referenced; purge/pseudonymize only through authorized retention job |
| BUSINESS | Sessions/requests/corrections/days/steps | Preserve audited history; legal period unresolved; no normal hard-delete API |
| SENSITIVE | Raw evidence/attachments/device tokens | Minimum permitted period, then controlled erase; consent and access audit |
| AUDIT | Ledger/decision actions/audit_log | Append-only application writes; protected archival/retention operations |
| PROJECTION | Ref/fact/summary tables | Rebuildable; retain source revision and refresh watermark |
| DELIVERY | Notifications/attempts/jobs | User-visible retention and signed-object cleanup; exact periods unresolved |
| TRANSIT | Outbox/inbox/idempotency | Pending rows never discarded; dedupe must cover replay horizon; command keys ≥30 days proposed |

The per-table purpose, constraints, and query indexes follow; common tenant filtering, retention, audit, and migration rules apply to every table. Every mutation of a BUSINESS/MASTER resource writes its owner's audit_log and, where cataloged, outbox in the same transaction. No cascade delete removes business evidence. FK defaults are restrictive. RLS is proposed defense-in-depth, not included in this DDL; runtime role grants and transaction-local tenant handling require integration tests.

Create schemas with a migration/admin role first; runtime roles must not own the entire database.

```sql
CREATE SCHEMA IF NOT EXISTS identity_org;
CREATE SCHEMA IF NOT EXISTS attendance;
CREATE SCHEMA IF NOT EXISTS leave;
CREATE SCHEMA IF NOT EXISTS request;
CREATE SCHEMA IF NOT EXISTS notification;
CREATE SCHEMA IF NOT EXISTS reporting;
```


### 4.2 Owner tables and DDL

### identityorg.tenant

Owner: `identity_org` service schema. Purpose: Tenant root; id itself is the isolation key.

Retention: MASTER; mutable current state; owner audit and version preconditions required.

PK and all FK/unique/check constraints are declared below; listed indexes serve tenant-scoped lookups/queues. If no extra index is listed, the primary/unique index serves the expected access path.

```sql
CREATE TABLE "identity_org"."tenant" (
  id uuid NOT NULL,
  name text NOT NULL,
  slug text NOT NULL UNIQUE,
  timezone text NOT NULL,
  country char(2) NOT NULL,
  status text NOT NULL CHECK (status IN ('ACTIVE','SUSPENDED')),
  deleted_at timestamptz,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),
  version bigint NOT NULL DEFAULT 1 CHECK (version > 0),
  PRIMARY KEY (id)
);
```

### identityorg.employee

Owner: `identity_org` service schema. Purpose: Employment record with optional tenant user link and same-tenant hierarchy.

Retention: MASTER; mutable current state; owner audit and version preconditions required.

PK and all FK/unique/check constraints are declared below; listed indexes serve tenant-scoped lookups/queues. If no extra index is listed, the primary/unique index serves the expected access path.

```sql
CREATE TABLE "identity_org"."employee" (
  tenant_id uuid NOT NULL,
  id uuid NOT NULL,
  user_id uuid,
  employee_no text NOT NULL,
  full_name text NOT NULL,
  phone text,
  department_id uuid,
  position_id uuid,
  manager_id uuid,
  hire_date date NOT NULL,
  terminated_on date,
  employment_type text NOT NULL CHECK (employment_type IN ('FULL_TIME','PART_TIME','CONTRACT')),
  status text NOT NULL CHECK (status IN ('ACTIVE','ON_LEAVE','TERMINATED')),
  device_id text,
  deleted_at timestamptz,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),
  version bigint NOT NULL DEFAULT 1 CHECK (version > 0),
  PRIMARY KEY (tenant_id,id),
  UNIQUE (tenant_id,employee_no),
  UNIQUE (tenant_id,user_id),
  FOREIGN KEY (tenant_id,user_id) REFERENCES "identity_org"."app_user" (tenant_id,id),
  FOREIGN KEY (tenant_id,department_id) REFERENCES "identity_org"."department" (tenant_id,id),
  FOREIGN KEY (tenant_id,position_id) REFERENCES "identity_org"."position" (tenant_id,id),
  FOREIGN KEY (tenant_id,manager_id) REFERENCES "identity_org"."employee" (tenant_id,id),
  CHECK (manager_id IS NULL OR manager_id <> id),
  CHECK (terminated_on IS NULL OR terminated_on >= hire_date)
);
CREATE INDEX "identity_org_employee_q1" ON "identity_org"."employee" (tenant_id,department_id,
  status,id);
CREATE INDEX "identity_org_employee_q2" ON "identity_org"."employee" (tenant_id,manager_id,id);
```
