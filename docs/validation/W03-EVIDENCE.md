## Accepted intent and current behavior

- ADR 010 and ADR 011 require the gateway and every Java service to validate access tokens with Spring Security OAuth2 Resource Server. Attendance, leave, request, notification and reporting now have local RS256/JWKS decoders and deny their unimplemented business routes after authentication. Gateway routed proof is covered by `OrganizationGatewayRoutingIT`.
- The employee wire shape decision is `employeeNo`, `departmentId` and `positionId`. Additive `/api/v2` operations now cover employee master, work sites, shifts, assignments and holidays while preserving prior `/api/v1` definitions. The gateway strips `/api/v2`; the provider exposes corresponding owner paths. Both clients map these paths to v2. Departments and positions remain at v1.
- The user accepted the archived employee/shift/holiday snapshot shapes as the provisional v1 organization event wire. ADR 012 and the new `organization-fact.v1.avsc` define one typed envelope and its three payload variants. Identity-org has an allowlisted outbox-to-Avro mapper and a disabled-by-default publisher candidate; attendance has a conditional consumer candidate. Their release gates remain open.
- Attendance migration V1 adds tenant-scoped employee, shift and holiday snapshot projections, inbox receipts and aggregate revisions. The projection service validates the owner envelope, commits receipt plus newer snapshot atomically, and rejects malformed or mismatched facts. A conditional Kafka listener acknowledges only after this transaction returns. A conditional startup runner replays compacted owner topics before readiness; its manual Kafka-container test passes, while Spring readiness and deployed listener acceptance remain open.
- The user selected `IDENTITY-UNAUTHENTICATED` and `IDENTITY-FORBIDDEN` for identity security problems. Existing identity assertions and the canonical `Problem.code` description were aligned; contract compatibility and identity unit tests passed. Other service error codes were not assumed to change.
- New, unapplied identity migrations V6–V10 create department, position, employee, command-receipt, work-site, shift, employee-shift, holiday, aggregate-revision, organization-outbox and private UUID-only relay-registry tables. Tenant-leading foreign keys and uniqueness, a manager-cycle trigger, a direct-SQL effective-period overlap guard, schedule checks and transaction-local RLS cover business rows. The runtime role has no BYPASSRLS grant in the provisioning script and no access to the separate job schema. The owner APIs have scoped reads/writes, ETags and command receipts for implemented POSTs. Assignment writes lock the employee and preserve a shift/site snapshot. Employee, shift and holiday mutations append tenant-scoped outbox intent in their transaction. A disabled-by-default single-leader relay candidate now waits for a broker acknowledgment before marking sent. This is not deployed provider acceptance.
- `infra/scripts/create-topic.sh` now targets Kafka's configured internal listener; `infra/scripts/register-organization-schema.sh` prepares and posts the reviewed envelope to the three value subjects. Syntax and Avro JSON checks pass. Neither script has been executed against the intended host or a real Schema Registry.
- The architecture simplification request replaces `Map<String, Object>` organization payload construction with typed employee/assignment, shift/site and holiday records in `OrganizationSnapshots`. `OrganizationFactMapper` now deserializes one typed record and converts it to Avro at publication; exact integer conversion rejects fractional and overflowing shift values. Employee pages fetch department and position names in two tenant-scoped batches. A shared revision precondition helper keeps all organization update ETag checks aligned. The relay logs the full failure cause while leaving the outbox row retryable. These are local refactors, not a change to the accepted wire, RLS, or delivery contract.

## Architecture simplification disposition

Of 24 recommendations, six have direct local changes, eleven were already represented or now have an explicit retention decision, one cited dependency is required, and six remain deferred by a contract or accepted-architecture constraint. The pasted checklist is guidance, not an accepted replacement for ADR 008 or ADR 012. Items 1–3, 6, 7 and 19 have direct local changes above. Items 9, 12–17, 20, 22–24 are already substantially represented by the single poller, transaction-local tenant scope, create-only receipts, centralized receipt persistence, database uniqueness and version fields, explicit event allowlist, focused integration tests, small services and existing ADRs. For item 16 the user chose to retain receipts indefinitely until a reviewed policy is approved; no cleanup is introduced. Item 8's cited `WorkSiteRepository` is used to build shift snapshots, so removing it would break the wire.
