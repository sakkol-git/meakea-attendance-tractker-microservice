# Shared HTTP contract baseline

Canonical source: `openapi.json`, OpenAPI 3.1 JSON. Status: provisional shared consumer requirements. The current working copy inventories 145 paths and 178 operations; new Week 3 employee and schedule operations remain provider-pending until routed acceptance. Only the shared leave detail/approval fixture currently has cross-client adapter evidence. An inventoried operation is not an accepted provider contract.

Run the commands in [project context](../docs/development/PROJECT-CONTEXT.md). `scripts/contracts.py validate` uses OpenAPI validation and JSON Schema validation of the shared synthetic fixture. `sync` creates versioned client copies plus a SHA-256 receipt; `check` rejects drift or missing clients. Standalone `check-bundle.py` is copied with the bundle and verifies integrity, not upstream freshness. Existing Avro contracts remain in `libs/hrflow-contracts/events/`.

Client tests exercise the actual web API wrapper and mobile feature repository with this fixture, including ETag preservation, request routes, command identity and failure propagation. They are consumer checks using simulated transport. Real provider tests, business transactions, security, browser CSRF/session negotiation and deployed-version compatibility remain required before integration acceptance. [ADR 012](../docs/adr/012-ORGANIZATION-EVENT-V1.md) owns the provisional typed organization event wire in `libs/hrflow-contracts/events/organization-fact.v1.avsc`; its Avro round-trip test does not prove Kafka delivery.

The compatibility checker preserves existing wire definitions conservatively and permits new paths/components and editorial edits. It is stricter than a semantic breaking-change tool and does not prove business compatibility. See the context guide for limits and versioning procedure.

## Attendance session integration candidate

On 2026-10-28 the owner required completing live attendance → Kafka → reporting → CSV integration before MVP readiness. `libs/hrflow-contracts/events/attendance-session-fact.v1.avsc` specifies the full effective session snapshot on the already documented `attendance.session.v1` topic with key `tenantId:employeeId`. Its positive aggregate revision is the committed JPA session revision plus one, not a fabricated constant. New sessions capture their assigned shift's work date, zone, UTC window and grace basis. Manual corrections remain explicit human decisions; raw telemetry and credentials do not enter the reporting event. Unsupported legacy rows with unknown schedule basis must remain visible as unresolved, never backfilled with guessed hours or shifts. This is an implementation candidate under the accepted architecture and requires real transport, replay and CSV evidence before acceptance. The older `AttendanceCheckedIn` wire is retained unchanged and is not promoted into a session snapshot.

The owner approved `GET /reports/exports/{id}/download` on 2026-10-28. The original requester must still authenticate as HR_ADMIN in the same tenant. Queued jobs omit the link; completed jobs return a relative `/api/v1/reports/exports/{id}/download` link. The file is streamed privately with `no-store`; unknown/foreign jobs return 404, unfinished jobs 409 and unavailable files 503. Web and mobile must fetch it using their authenticated API transport, not browser navigation or anonymous signed-file transport. Attendance CSV contains effective session facts, including captured zone, actual timestamps, state, source and revision; it does not assert finalized daily absence or leave precedence. Leave/request sources and legacy rows without a schedule basis remain separate acceptance gaps.

## Leave lifecycle snapshot implementation

The existing approved `leave.request.v1` topic uses `tenantId:employeeId`. The new `leave-request-fact.v1.avsc` implementation contract carries a full owner snapshot: stable envelope/event ID, actual positive owner aggregate revision, employee/type, date range, portion, exact charged-day decimal string, actual expanded working dates and lifecycle state. These fields come from the persisted leave owner, not a reporting estimate. The snapshot excludes reason, name and medical/supporting evidence. Pending/approved/rejected/cancelled/review states remain the owning leave workflow's states; transport does not decide policy or compensation. Existing schema-0 rows are not relabeled. Registry registration/compatibility, acknowledgment/retry, consumer receipt/effect transactions, cancellation/revision handling and replay require separate executed checks before UAT acceptance.

`attendance-daily-fact.v1.avsc` is the explicit provisional full snapshot for approved architecture §11.5–11.7 on `attendance.daily-status.v1` (key `tenantId:employeeId`). It carries a stable day aggregate with positive monotonic revision, calendar type, flags, nullable completed duration, finalization, expected instants and the actual session/leave revisions used. Work/leave overlap remains reviewable with debit unchanged; early/cutoff/equal-half policy follows the 2026-10-28 user decisions. Historical session-only facts are never relabeled daily facts. Producer, live consumer and broker compatibility checks are independent evidence gates.

`shift-cutoff-fact.v1.avsc` specifies the accepted `time.shift-cutoff.v1` trigger (§11.6), keyed `tenantId:employeeId`. It carries the actual shift/day/zone basis and cutoff instant (shift end + accepted 30 minutes); stable per-day aggregate revision is 1. A durable cursor starts on the first verified local day observed by the opt-in worker and catches up subsequent missed days. No pre-enrollment historical absence is invented. Readiness and migration/replay tests remain separate gates.
